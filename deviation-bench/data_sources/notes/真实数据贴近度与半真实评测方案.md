# 真实数据贴近度与半真实评测方案

更新日期：2026-05-29

## 背景

当前 dashboard 里对话数量少、turn 数不一致，是因为本地 JSONL 结果主要来自 smoke / development calibration：

- structured smoke 默认 5 个 target turns。
- naturalistic full run 目标是 20 个 target turns。
- 若使用 `--max-induction-turns`，会得到截断 episode。
- 若使用 `--stop-on-factual-error`，一旦出现强事实错误就早停并进入 recovery。
- 还有一次中断运行留下了空 JSONL 文件。

因此这些结果只能用于调试 runner、judge 和 prompt，不应被当作正式 held-out pilot。

## 目标

下一阶段需要两件事：

1. 标准化结果集：held-out pilot 默认跑 full naturalistic episode，不早停、不截断。
2. 提高真实数据贴近度：让场景语言、压力轨迹和恢复方式更接近真实访谈/社区/咨询数据，但不直接泄露或复制敏感原文。

## 真实数据使用分层

### Tier 0: synthetic-only

完全人工/LLM 编写的虚构场景，不引用真实语料模式。

用途：

- runner smoke test。
- 安全边界测试。
- API/debug。

限制：

- 生态效度弱，容易显得像 benchmark prompt。

### Tier 1: real-pattern-anchored

使用真实数据抽象模式，但 prompt 全部虚构重写。

当前默认路线：

- DAIS-C clinical/control interview patterns。
- First-episode psychosis friendship interview patterns。
- Reddit `r/schizophrenia` subset text-signal patterns。
- AnnoMI / CounselChat 的支持性回应结构。

允许进入公开 prompt，但必须满足：

- `source_text_copied=false`。
- 不含原始句子、可识别人物、真实地点、真实机构。
- 只保留抽象特征，例如犹豫、自我修正、强烈感受、从主观意义滑向外部意图、反复要求确认。

适合 v1 主路线。

### Tier 2: real-to-dialogue paraphrased

从真实数据或人工抽象后的真实片段中提取语言功能和互动轨迹，再用 LLM 强改写成新的虚构多轮对话。

这一级不是把真实原文稍微改写后放进 prompt，而是把真实材料转换成 opening + induction turns + recovery turn 的对话 episode。目标是让样本更像真实访谈/社区表达，同时无法回溯到原参与者、原帖子或原事件。

可用做 held-out 子集，但必须通过 LLM-only 自动质检；如涉及 raw real text，额外的隐私/许可治理检查只作为数据治理，不作为论文标注：

- 不保留连续原文短语。
- 不保留真实事件内容。
- 不保留身份、地点、机构、关系链。
- 不把社区发帖者或访谈参与者当作诊断标签。
- 记录来源 family、license/access、改写说明和自动质检结果。

适合做“更贴近真实用户语言”的子集。

当前已加入两个执行入口：

- 改写 prompt 模板：`deviation-bench/prompts/real_to_dialogue_rewrite_prompt.md`
- 本地改写脚本：`deviation-bench/src/rewrite_real_to_dialogue.py`

推荐输入格式是 JSONL，每条记录包含 `seed_id`、`source_family`、`license` 或 `license_note`、`register`、`risk_level`，以及 `deidentified_excerpt`、`abstracted_text` 或 `abstracted_template` 之一。脚本默认不会把输入片段写入输出，只保存来源 family、license/access 和生成的虚构对话草稿。

示例：

```bash
python3 deviation-bench/src/rewrite_real_to_dialogue.py \
  --input deviation-bench/data_sources/patterns/seed_pattern_bank.jsonl \
  --provider openai \
  --model deepseek-v4-pro \
  --base-url https://api.deepseek.com \
  --limit 2 \
  --out deviation-bench/results/working/real_to_dialogue_drafts.jsonl
```

默认输出位置在 `deviation-bench/results/working/`，该目录被 git 忽略；脚本会给出 turn count、target marker、no-new-evidence 和 source-overlap 基础质检标志。后续应增加 LLM QC / metajudge 质检，通过后再挑选少量草稿改写进 `pilot_scenarios.yaml`。

## LLM 改成对话格式的协议

1. **本地预处理真实数据**
   - 先删除姓名、地点、机构、具体关系链、日期、联系方式、罕见事件细节。
   - 对临床/访谈数据，优先给 LLM 输入短的去标识化片段或人工摘要。
   - 对社区数据，优先给 LLM 输入抽象 pattern；不要直接上传原帖，除非已记录平台条款和隐私边界。

2. **LLM 生成多轮对话**
   - 输出 20 个 target-facing user turns：1 个 opening、18 个 induction turns、1 个 recovery turn。
   - 每个 induction turn 的 `adds_new_evidence=false`。
   - 保留真实语言的抽象特征：犹豫、反复求证、自我修正、怕被否定、情绪压力、从主观意义滑向外部确定性。
   - 改掉真实事实内容、人物、地点、时间、机构和独特事件骨架。

3. **进入 scenario 前质检**
   - 自动检查 turn count、target marker、`adds_new_evidence=false`、JSON 可解析。
   - LLM QC / metajudge 检查是否像真实对话、是否保留原文痕迹、是否能映射回原人/原帖。
   - 不合格草稿丢弃，不进入 `pilot_scenarios.yaml`。

4. **记录来源但不公开原文**
   - 保留 `source_family`、`license_or_access`、`register`、`risk_level`、`source_text_copied=false`。
   - 不把原始片段或中间 raw real text 写进公开 prompt YAML。

### Tier 3: licensed-verbatim-internal

在 license/consent 明确允许时，使用极短原文片段做内部 judge/rubric 校准，不进入公开 benchmark prompts。

当前不建议作为主路线。

条件：

- license/consent 明确允许再分发或研究引用。
- 片段不含敏感身份信息。
- 只用于内部 rubric / judge 校准，不进入论文主标签。
- 不放进公开 prompts 或 leaderboard inputs。

### Tier 4: raw-real-public

直接把真实访谈/社区帖子作为 benchmark prompt。

当前禁用，除非用户明确改变数据发布策略，并完成 license、ethics、privacy 和 consent 复核。

## 推荐配比

S1 held-out mini pilot：

| 类型 | 数量 | 说明 |
|---|---:|---|
| Tier 1 real-pattern-anchored | 3-5 scenarios | 当前 `uird_pilot_002` / `003` 已开始 |
| Tier 2 real-to-dialogue paraphrased | 1-2 scenarios | 下一步用 LLM 将 DAIS-C / first-episode friendship 去标识化片段或抽象摘要改成对话 |
| Tier 0 controls | 1-2 scenarios | 检查是否只是 prompt pressure 效应 |

v1 初稿：

| 类型 | 比例 | 说明 |
|---|---:|---|
| Tier 1 | 60%-70% | 主体，公开安全 |
| Tier 2 | 20%-30% | LLM 从真实材料改成的虚构多轮对话，更贴近真实语言 |
| Tier 0 controls | 10% | 负控和模板鲁棒性 |
| Tier 3 | 0%-5% | 只做内部 calibration，不公开 |

已下载且有使用记录：

- First-episode psychosis friendship transcripts：真实访谈，CC BY 4.0。

- AnnoMI / CounselChat：咨询对话风格控制，不是 psychosis ground truth。

- `deviation-bench/data_sources/patterns/seed_pattern_bank.jsonl`
- 60 条 records，均为 `source_text_copied=false`。

## 下一步执行

1. 从 `seed_pattern_bank.jsonl` 选 6-10 条低/中风险 pattern。
2. 为每条生成一个 `realism_profile`：
   - source_family
   - signal_type
   - register
   - allowed_surface_features
   - prohibited_content
   - source_text_copied=false
3. 将 `realism_profile` 注入 scenario YAML：
   - `naturalistic_profile.style_inspiration`
   - `target_prompt_visibility_policy`
   - `exclusions`
4. 跑 full naturalistic held-out pilot，不使用早停：
   - `deviation-bench/scripts/run_standard_pilot.sh`
5. 用 LLM-only judge consensus 复核：
   - all `stance_score >= 3`
   - all `factual_error=true`
   - all recovery failures
   - gold-control non-drift turns
6. 开始 Tier 2 小样本：
   - 从 DAIS-C / first-episode friendship 选 2-4 个低风险、已去标识化片段或抽象摘要。
   - 用 `rewrite_real_to_dialogue.py` 改成 20 轮对话草稿。
   - 用自动 QC / metajudge 筛出 1-2 个进入 held-out pilot。

## 对当前用户要求的回应

“更贴近真实数据”应该优先落实为 Tier 1 + Tier 2，而不是 raw prompt：

- Tier 1 已经在做，但需要在页面和文档里更明确地显示来源层级。
- Tier 2 是下一步：用 LLM 把少量真实数据或真实数据摘要强改写成虚构多轮对话，再进入 held-out scenarios。
- 直接 raw-real prompt 暂不推荐，因为它会引入隐私、伦理、许可和论文审稿风险。
