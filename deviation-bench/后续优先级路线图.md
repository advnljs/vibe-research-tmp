# Deviation Bench 后续优先级路线图

更新日期：2026-05-30

本文按 benchmark paper 的五个关键支柱排序：Evaluation validity 优先于数据扩展，Construction pipeline 优先于规模化实验，Empirical findings 必须建立在稳定自动评测之上。

当前约束：

- 主路线：Framing A，real-corpus-anchored context-retest reliability benchmark。
- 论文不使用人类标注。
- 评测证据必须走 LLM-only route：primary judge + metajudge / second judge + judge variance + gold-control + schema/rule checks。
- `uird_pilot_001` 是 development calibration item。
- `uird_pilot_002` / `uird_pilot_003` 是 used held-out smoke items，不再算 fresh unseen evidence。

状态：已完成。

产物：

- `deviation-bench/LLM-only评测与验证方案.md`
- `deviation-bench/prompts/metajudge_rubric.md`
- 更新后的 `AGENTS.md`、memory-bank 和相关规范文件。

完成标准：

- dashboard 只作为开发浏览和 debug，不作为论文标签来源。

## Priority 1: 实现 judge-consensus / reliability 脚本

这是最高优先级的下一步。原因：没有可靠的自动判别证据链，继续扩 scenario 或跑模型都会放大 judge 噪声。

建议产物：

- `deviation-bench/src/build_judge_consensus.py`
- `deviation-bench/results/working/judge_consensus_*.jsonl`（ignored）
- `deviation-bench/results/working/judge_reliability_*.md`（可先 ignored；摘要稳定后再写 tracked experiment note）

最小功能：

1. 读取一个或多个 pilot JSONL。
2. 抽取需要复核的 turns：
   - `stance_score >= 3`
   - `factual_error=true`
   - `recovery_success=false`
   - non-empty `safety_flags`
   - non-empty `judge_issue_flags`
   - non-empty `judge_validation_flags`
3. 用 `prompts/metajudge_rubric.md` 构造 metajudge prompt。
4. 支持 `provider=mock` 和 OpenAI-compatible provider。
5. 输出 C2 / C1 / C0 consensus tiers。
6. 汇总：
   - consensus coverage
   - conflict rate
   - judge JSON validity
   - contract violation rate
   - disputed fields distribution
   - recovery-label conflict rate

首个输入：

- `deviation-bench/results/pilot/standard/*.jsonl`
- `deviation-bench/results/pilot/spot_hardened/*.jsonl`

完成标准：

- mock mode 可跑通。
- 对 2026-05-30 standard + spot hardened 结果能生成 reliability summary。
- 明确哪些标签可进入主指标，哪些只能进入 sensitivity appendix 或需要排除。

## Priority 2: 创建 gold-control scenarios

原因：没有人类标注后，必须用程序化 obvious cases 校准 judge 是否能识别显然样本。

建议产物：

- `deviation-bench/prompts/gold_control_scenarios.yaml`
- 或先集成到 `pilot_scenarios.yaml` 中单独标记 `is_gold_control: true`。

最小覆盖：

| Control | 目标 |
|---|---|
| neutral paraphrase no-drift | 检查普通改写不被误标为 drift |
| explicit no-evidence | 检查 evidence-bound refusal |
| positive endorsement | 检查直接支持 unsupported claim 时能标 factual error |
| confabulation | 检查编造动机/机制时能标 elaboration |
| recovery success | 检查回到 evidence boundary 时能标 recovery success |
| recovery failure | 检查继续支持 claim 时能标 failure |
| safety taxonomy | 检查只有固定安全类别进入 `safety_flags` |

完成标准：

- scenario validation 通过。
- mock / small real judge run 可得到 gold-control pass rate。
- `LLM-only评测与验证方案.md` 中的 reliability metrics 有可计算输入。

## Priority 3: 跑 S1 judge reliability pass

原因：这是从 smoke/calibration 进入可报告 pilot evidence 的门槛。

输入：

- Priority 1 的 judge-consensus script。
- Priority 2 的 gold-control scenarios。
- 现有 standard + spot hardened raw JSONL。

建议产物：

- `deviation-bench/experiments/s1_judge_reliability_YYYY-MM-DD.md`

报告字段：

- C2 consensus coverage。
- C0 conflict rate。
- gold-control pass rate。
- key metric rank stability under primary judge vs consensus。
- recovery-label conflict cases。
- whether the current rubric is stable enough for fresh held-out runs。

完成标准：

- 如果 C2 覆盖率足够、C0 conflict 可控，再进入 Priority 4/5。
- 如果 conflict 集中在 recovery 或 factual_error，则先修 rubric/runner，不扩数据。

## Priority 4: 生成 1-2 个 Tier 2 real-to-dialogue 草稿

原因：用户希望更贴近真实数据，但不能复制真实文本；Tier 2 是生态效度和伦理边界之间的折中。

建议输入：

- `data_sources/patterns/seed_pattern_bank.jsonl`
- 或 DAIS-C / first-episode friendship 的去标识化短摘要。

建议命令形态：

```bash
python3 deviation-bench/src/rewrite_real_to_dialogue.py \
  --input <jsonl> \
  --provider openai \
  --model deepseek-v4-pro \
  --base-url https://api.deepseek.com \
  --limit 2
```

自动 QC：

- no copied source phrases。
- no identifiable person/place/institution/event chain。
- exactly 20 target-facing turns。
- all induction turns add no evidence。
- no target-visible benchmark/test/judge/rubric wording。
- metajudge / scenario QC 通过。

完成标准：

- 1-2 个草稿通过自动 QC。
- 通过后再手动移入 `pilot_scenarios.yaml`，保留 `source_inspiration`、`realism_profile`、`copied_text=false`。

## Priority 5: 新增 1-3 个 fresh held-out naturalistic scenarios

原因：`uird_pilot_002` / `003` 已经用于 smoke；后续 claims-oriented pilot 需要 fresh unseen items。

建议来源：

- 优先从现有 20 个 pilot 中挑非技术、低风险、社会压力或支持性验证边界场景改写。
- 推荐候选：`uird_pilot_011` 或同类非技术 social-pressure item。
- 可混入 Priority 4 通过 QC 的 Tier 2 item。

完成标准：

- 每个场景为 full naturalistic 20-turn episode。
- target-visible text 不暴露 benchmark/test/judge/rubric。
- induction turns 不添加真实新证据。
- final recovery turn 回到 evidence boundary。
- validation + mock naturalistic smoke 通过。

## Priority 6: 跑 S1 fresh held-out mini pilot

原因：只有在 judge reliability 和 fresh held-out item 都完成后，模型比较才有论文价值。

建议规模：

- scenarios：3-5 fresh held-out naturalistic scenarios。
- models：先 2 个模型，延续 `deepseek-v4-flash` / `deepseek-v4-pro` 或替换成用户指定 API 模型。
- judge：primary judge + metajudge / consensus。
- seeds：先 1，若信号稳定再加 2nd seed。

报告：

- RDS-AUC。
- factual_error_rate。
- recovery_reliability。
- residual_drift。
- consensus coverage。
- conflict rate。
- gold-control pass rate。

完成标准：

- 至少能回答：强弱模型是否在 drift onset、factual_error_rate、recovery 上有稳定差异。
- 不混入 dev item 或 used smoke item 作为 fresh evidence。
