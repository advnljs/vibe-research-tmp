## 0. 本文档遵循的科研工作流

本文档**不**给出一个 AI 拍板的研究方向。按 `vibe-research-workflow` 的六条行为规则之第 2 条——“研究思路、问题、设计、技术路线、实验计划、核心结论必须用户自有且充分理解”，本文只把项目自带工作流当作思考脚手架，对“收缩目标 + 重打包真实数据”这个用户提议做三件事：

- 用 `idea-evaluator` 的 Fatal-flaws / Five-dimensions / Paradigm-shift probe / Feasibility 给候选 framing 系统打分；
- 用 `benchmark-paper-template` 的五大支柱（Research Gap / Construction Pipeline / Evaluation Framework / Empirical Findings / Companion Method）逐一检查每个 framing；
- 把决策点明确剥离出来，列在最后让用户自己选。

整篇文档遵循 §0.1 的脚手架，严格按 §0.2 的输出格式产出。

### 0.1 工作流摘要（来自三个 skill）

**idea-evaluator 八步**：First impression → Fatal-flaws audit（10 类，CRITICAL 一票否决并 short-circuit 出 Reject）→ Lifecycle / capability matching → Five-dimension scoring（Higher / Faster / Stronger / Cheaper / Broader）→ Paradigm-shift probe（First Principles / Elephant / Tech Cycle / Hamming）→ Feasibility check（Compute / Data / Engineering / Timeline）→ Integrity gate → Verdict（Strong Accept / Accept w. Revisions / Reject and Pivot）。

**benchmark-paper-template 五大支柱**：

1. Research Gap：必须是 Dimension Blindness / Assumption Violation / Granularity Mismatch 三种 gap pattern 之一，且通过 4-项 validation。
2. Construction Pipeline：Reverse Synthesis / Controlled Injection / Adaptive Generation + Expert Annotation 三种范式选一或组合。
3. Evaluation Framework：taxonomy + per-dimension rubric + auto/LLM-judge/human 三选一或组合，且 LLM judge 必须做与人审的一致性校验。
4. Empirical Findings：每条以 “Finding X: ……” 的 lemma-like 句式呈现，必须 actionable。
5. Companion Method（可选）：能放就放，benchmark 强度跳一档。

Design Goals 必须显式覆盖 G1 Coverage、G2 Diagnostics、G3 Scalability、G4 Quality。Difficulty Calibration：top models 在最难子集上目标准确率 0.1-9%。

**vibe-research-workflow 行为约束**：AI 只做 mechanical 加速 / 文献组织 / 代码与调试 / 语言润色；研究判断、问题设计、核心结论、引用必须用户自有；不伪造引用；不学术不端。

### 0.2 输出格式

逐 framing 用 idea-evaluator 的 §1-§8 格式 + benchmark-paper-template 的五大支柱表，附统一对比表，再列用户必答的开放决策点。

  - F1 与 weval / Stanford HAI / ELEPHANT 的差异化要在 introduction 第一段就讲清楚；
  - F7 不能再依赖未到位的 PsychosisBank 等受限源；
  - F8 不能同时承诺 benchmark + 新指标 + companion method + multi-turn UIRD。

## 3. 三个候选 framing 的系统评估

下面每个 framing 都按 idea-evaluator 八步 + benchmark-paper-template 五支柱给出**对称的**评估，便于 §4 横向对比。本文**不**替用户挑 framing。

### 3.A Framing A: 真实语料锚定的 Context-Retest Reliability Benchmark

> **一句话故事**：把 9 个真实临床/社区/咨询语料统一为一个 utterance corpus，让 LLM 对同一 grounded 判断题在不同真实 context wrapping 下回答，测「同题在不同真实分布 context 下的判断一致性」。

**§1 First impression**
- Paper type：**New Setting**（新评估视角 + 新 corpus 组合）
- 一句话：context-retest reliability，第一次完全基于真实跨源语料且单轮可复现。

**§2 Fatal-flaws audit**

| # | Flaw | Severity | Defense |
|---|---|---|---|
| F1 | 与 weval `ai-psychosis.yml`、Stanford HAI eval、ELEPHANT 的差异 | MAJOR | 差异化点：**跨多个真实源 + 同题多 context 一致性 + retest 指标**；前者是单源单 blueprint 单轮，未做 cross-context retest |
| F4 | 谁会因此受益 | MINOR | AI deployment safety、AI psychosis 现象（已有新闻级公共影响） |
| F8 | scope 是否过大 | MINOR | 单轮 + 单一指标族，scope 干净 |
| F10 | 失败模式 | MINOR | 显式列：context 引入新事实即不合规、judge 与人审 κ < 0.4 即 invalidate |

无 CRITICAL，可继续。

**§3 Lifecycle / capability matching**
- Idea category：**Data-intensive**，lifecycle 6-12 个月。
- 用户约束：API only / 低 GPU / 中等 API 预算 → match。
- 估算：data ETL 2 周 + schema + 跑评估 2 周 + 人审 1 周 + 写作 4 周 + 修改 2 周 ≈ 11 周。**Green**。

**§4 Five-dimension**

| Dim | Score | Evidence |
|---|---:|---|
| Higher | 3 | 不是“准确率提升”类工作 |
| Faster | 3 | 评估管线快但不是卖点 |
| Stronger | 7 | 真实分布下 robustness 是核心 |
| Cheaper | 8 | API only、无合成成本、无 GPU |
| Broader | 7 | 跨临床/社区/咨询多源 unification |

Top 2 lift：Stronger + Broader + Cheaper。

**§5 Paradigm-shift probe**

| 探针 | Yes/Partial/No | 理由 |
|---|---|---|
| First Principles | Yes | 挑战“situational consistency”隐含假设 |
| Elephant | Partial | AI 心理化现象社区已注意到但缺统一评估 |
| Tech Cycle | Partial | frontier LLM 让 retest 测量成本可承受 |
| Hamming | Partial | 成功会改变 AI safety eval 习惯 |

Probe 分：~5/8。**Disruptive potential：possible**。

**§6 Feasibility**

| Risk | Level | Mitigation |
|---|---|---|
| Compute | Low | API only |
| Data | Low | 现有数据已落地，无受限源依赖 |
| Engineering | Medium | 需要写一套统一 schema ETL + LLM-as-judge pipeline + 人审 audit |
| Timeline | Medium | 11 周内可完成，前提是 scope 严格 |

**§7-8 Verdict 视角**：Accept with Revisions（取决于 F1 差异化是否写清楚）。

**Pillar 检查（benchmark-paper-template）**

| Pillar | 状态 | 说明 |
|---|---|---|
| Research Gap | 强（Pattern B: Assumption Violation）| 现有 eval 假设 user input 是 well-formed query；真实部署中 user input 可能含 reality-boundary 语言；模型在这类输入下的 context-retest 没有系统评估 |
| Construction Pipeline | 强（Paradigm 2: Controlled Injection，注入 context wrapping）| 不同 context wrapping 即 controlled injection 的 wrapping 维度 |
| Evaluation Framework | 中→强 | 主指标候选：Context-Retest Reliability (CRR)、Deviation Index (DI)、Cross-Source Variance、Validation Language Rate；taxonomy: 5 sources × 4 context wrappings |
| Empirical Findings | 待跑 | 期望发现：模型 capability 与 reality-boundary 真实语料 wrapping 下的判断稳定性弱相关，frontier 模型不一定更稳 |
| Companion Method | 可选 | 可以加一个 “grounding prompt + retest score 反馈微调（DPO）” 的小型 companion，但单论文可不做 |

**G1-G4 Coverage**：G1（5 真实源覆盖 reality-boundary 主要类别）、G2（per-source × per-wrapping 细粒度）、G3（管线 API only 可扩展）、G4（IAA 人审 + LLM-judge cross-validation）。

**关键 tradeoff**：放弃 multi-turn user induction dynamics（原 UIRD 核心）；用单轮多 wrapping 替代多轮单 wrapping。

### 3.B Framing B: 真实语料上的 LLM 响应质量评估 Benchmark

> **一句话故事**：把社区/临床/咨询真实 utterance 当单轮用户消息，评估 LLM 回答是否做到 grounding、不过度 validate、安全 escalation；AnnoMI/CounselChat 提供 reference good-response。

**§1 First impression**
- Paper type：**New Setting**（real-corpus-anchored response evaluation）
- 一句话：把 LLM 当“假设的 first responder”，在真实 reality-boundary user message 上测它是否表现安全。

**§2 Fatal-flaws audit**

| # | Flaw | Severity | Defense |
|---|---|---|---|
| F1 | 与 Stanford HAI mental health safety eval、weval `ai-psychosis.yml` 重叠 | **MAJOR** | 必须以“跨临床+社区+咨询多源 + 真实分布单轮 + LLM-as-judge 与 AnnoMI reference 双校准”立差异；如果讲不清易被 reject |
| F4 | 受益方 | MINOR | clear：AI 部署中遇到 vulnerable user 的安全决策 |
| F7 | 数据涉及社区帖直接用 | **MAJOR** | 必须严格去标识 + 抽象重写，否则违反项目 AGENTS.md 安全规则；或者只用 LLM 改写的 paraphrased 版本 |
| F8 | scope | MINOR | 单轮单任务可控 |
| F10 | 失败模式 | MEDIUM | 需预先列 over-validation、over-refusal、过度 escalation 三类 |

无 CRITICAL；但 F1 + F7 两个 MAJOR 同时存在 → 评级倾向 **Accept with Revisions**，必须先解决两个 MAJOR 才能动手。

**§3 Lifecycle / capability matching**：Data-intensive，6-12 个月，**Green**（与 A 同）。

**§4 Five-dimension**

| Dim | Score | Evidence |
|---|---:|---|
| Higher | 3 | 非准确率类 |
| Faster | 3 | – |
| Stronger | 6 | 测真实分布下 response robustness |
| Cheaper | 8 | API only |
| Broader | 6 | 跨多源但更聚焦“response quality” |

Top 2：Cheaper + Stronger。

**§5 Paradigm-shift probe**：
- First Principles：Partial（不是挑战 situational consistency，而是 user-side 反向问题）
- Elephant：Yes（AI psychosis spiral 是被避谈的具体问题）
- Tech Cycle：Yes（frontier LLM 之前这类响应都太弱不值得测）
- Hamming：Partial

Probe 分：~5/8。Disruptive potential：possible。

**§6 Feasibility**

| Risk | Level | Mitigation |
|---|---|---|
| Compute | Low | – |
| Data | Medium | 真实社区帖必须 paraphrase/抽象；F7 |
| Engineering | Medium | – |
| Timeline | Medium | 与 A 相当 |

**Pillar 检查**

| Pillar | 状态 |
|---|---|
| Research Gap | 中（Pattern C: Granularity Mismatch；现有 eval 粗粒度，本工作多维细粒度） |
| Construction Pipeline | 中（Paradigm 3: Adaptive Generation + Expert Annotation，真实素材 → LLM 抽象 → 人审） |
| Evaluation Framework | 强（grounding / validation / escalation 三轴，AnnoMI 提供 reference 让 LLM-as-judge 可靠） |
| Empirical Findings | 待跑 |
| Companion Method | 可选（safety fine-tune 小实验） |

**关键 tradeoff**：与 weval / Stanford HAI 已有 eval 重叠度最高，差异化必须在 introduction 第一段就压得住；同时社区数据的去标识 / 抽象步骤增加合规工作量。

### 3.C Framing C: A 为主榜 + 小型 LLM 合成 UIRD 子轨

> **一句话故事**：主榜走 Framing A 的 cross-corpus context-retest（完全真实数据），但保留 30-50 条 LLM 合成的 multi-turn UIRD 场景作为 “Dynamics Subtrack”，给原 UIRD 初心留一个接口。

**§1 First impression**
- Paper type：**New Setting**（主）+ Novel Problem（子轨）
- 一句话：cross-source reality-anchor benchmark 主榜 + multi-turn drift 子榜，全部 API-only。

**§2 Fatal-flaws audit**

| # | Flaw | Severity | Defense |
|---|---|---|---|
| F1 | 同 A | MAJOR | 同 A 的差异化 |
| F8 | scope 是否过大 | **MAJOR** | 主榜 + 子榜两条线，必须显式说明子轨是 future-work bridge 而非主结论，否则会被 reject 为 “unfocused” |
| 其余 | – | – | 与 A 同 |

无 CRITICAL；但 F8 是真实的 MAJOR。

**§3 Lifecycle / capability matching**：Data-intensive → 上沿，**Yellow**（12-15 周）。

**§4 Five-dimension**：基本同 A，但 Broader +1（多了 dynamics 维度），Cheaper -1（合成子轨增加 ~$15-35 API 成本和半天人审）。

**§5 Paradigm-shift probe**：与 A 相同分（~5/8），但 Elephant 项可升到 Yes（multi-turn drift 是被关注但未系统量化的现象）。

**§6 Feasibility**

| Risk | Level | Mitigation |
|---|---|---|
| Compute | Low | – |
| Data | Low | – |
| Engineering | Medium-High | 双 track 需要两套 pipeline，标注规范不一致风险 |
| Timeline | Medium-High | 子轨加 ~3 周，整体接近 lifecycle 上限 |

**Pillar 检查**：与 A 相同；多一个 Companion 候选——“在合成子轨上做 small DPO 微调，看是否减少 drift”。

**关键 tradeoff**：保留原 UIRD 初心，但 F8 scope 风险显著；需要论文 narrative 上做出“主-辅”清晰分层（如把子轨放进 §6 Discussion + Research Opportunities，而不是放进主实验）。

## 4. 三方案横向对比

| 维度 | Framing A | Framing B | Framing C |
|---|---|---|---|
| Paper type | New Setting | New Setting | New Setting + Novel Problem |
| Gap pattern | Assumption Violation | Granularity Mismatch | Assumption Violation + extension |
| Construction paradigm | Controlled Injection | Adaptive Generation + Expert | A + 小型 Adaptive 合成 |

| 不适合的人 | 想做 dynamics 的 | 想做 retest 的 | 想做单一 contribution paper 的 |

## 5. 我的倾向（不是替用户决策）

按 vibe-research-workflow 规则 2，最终 framing 必须用户自有。下列倾向只是 AI 基于上述分析给出的概率性观察：

- **如果用户优先 minimize fatal-flaw 风险且想第一篇 benchmark 干净落地**：Framing A 概率最高，因为只有 1 MAJOR flaw，且差异化点容易写清。

## 6. 与 framing 选择无关、可以立刻做的下一步

不管最终选哪个 framing，下列动作都必须做且不会浪费：

1. **写 Table 1（Benchmark Comparison Table）草稿**：把 weval `ai-psychosis.yml`、`ai-spiral-safety.yml`、Stanford HAI eval、ELEPHANT、`sycophancy-probe`、`hallucination-probe`、`mental-health.yml` 七个 prior 横向比较，列出各自的（task scope, source type, # sources, multi-source unified, retest, multi-turn, real-corpus-anchored, language）等列；这是 introduction 写作和 F1 差异化的必备资产。预计 2 小时。

2. **跑 §4 Phase A 的 real-API smoke test**（前文方案文件已具体化）：选 1 target + 1 judge，用现有 20 mock 场景中的 2 条跑通真实 API，验证 JSON contract 与 judge 稳定性。预计半天。

3. **从 DAIS-C clinical speaker-only + Reddit r/schizophrenia 抽 50-80 条 abstracted pattern**（前文方案文件 §6.5.7 第 6 项）：不复制原文，只存 (signal_type, theme, register, abstracted_template)；落到 `data_sources/patterns/seed_pattern_bank.jsonl`。Framing A/B/C 都需要这个 pattern bank（A 作 context wrapping 来源，B 作 utterance 抽样依据，C 作子轨合成 seed）。预计 2-3 小时。

4. **统一 utterance schema 草稿**（不管哪个 framing 都要）：定义 `(utterance_id, source, source_type, language, abstracted_text, signal_type, license, citation)` 八字段；落到 `prompts/utterance_schema.yaml`；用 DAIS-C 一个文件 + Reddit 10 条做小样本 ETL 试跑。预计 2-3 小时。

5. **写 Section 2 §Task and Design Goals 草稿（不超过 1 页）**：把 G1-G4 显式回答；这是 benchmark paper 必备结构件，先用项目当前事实写一版骨架，框架选定后再细化。预计 1 小时。

完成 1-5 后，进度独立于 framing 决策，且任何 framing 都能继续接力。

## 7. 用户必须自己回答的开放问题

按 vibe-research-workflow 规则 2，下列问题不能由 AI 替答：

Q1. **目标 framing**：A / B / C 选哪个？或还有第 4 种 framing AI 没列到的，由用户提出。
Q2. **目标 venue**：NeurIPS D&B Track / ACL Findings / EMNLP Industry / Workshop？这直接决定 baseline 数量（NeurIPS D&B 通常需要 ≥10 模型）、写作风格、figure 预算。
Q3. **是否做 companion method**：A/B/C 都标“可选”，但用户的 PhD portfolio strategy 决定要不要带；带了能拉高 paper strength 但多 3-4 周工程量。
Q4. **language scope**：只做 zh，还是 zh+en？现在 20 mock 场景全 zh；真要进 NeurIPS 主榜需要 en。
Q5. **DAIS-C / First-Episode Psychosis 的使用边界**：CC BY-SA / CC BY 4.0 允许重分发，但项目 AGENTS.md 明确要求“不直接复制可识别敏感原文”，因此 utterance schema 中 `abstracted_text` 究竟保留多少原文风格，需要用户给一个具体阈值（如：每条 ≤ 80 词、不保留任何 ≥ 8 词的连续片段、人工去身份化）。
Q6. **submission timeline**：哪个 deadline 倒推 lifecycle？这直接决定 Framing A vs C 的 yellow/green 判定。

回答 Q1-Q6 后，本文档可以直接转成 §6 那 5 个动作之外的 framing-specific roadmap。
